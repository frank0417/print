# PrintKit 设计文档

> 版本：0.3.0（对齐现有实现）  
> 仓库：https://github.com/frank0417/print  
> 目标：用 Chrome 扩展 + 本地 Native Messaging 代理，兼容经典 **jatoolsPrinter / JCP** API，实现网页精确分页打印与静默打印。

---

## 1. 背景与目标

### 1.1 问题

业务系统（尤其是 ERP / 仓储 / 票据）长期依赖 **jatoolsPrinter（JCP）** 实现：

- 按 `page1` / `page2`… DIV 精确分页
- 指定纸张、边距、方向、份数
- `print(myDoc, false)` 静默打到指定打印机

JCP 为闭源客户端，Chrome 扩展商店与跨平台维护成本高；业务侧希望有可替换、可自托管的开源方案。

### 1.2 目标

| 目标 | 说明 |
| --- | --- |
| API 兼容 | 页面可继续调用 `jatoolsPrinter.print / printPreview / getPrinters` |
| 精确分页 | 以 DOM `id=pageN`（可带前缀）为页边界，而非浏览器默认分页 |
| 静默打印 | Windows / macOS 不弹系统打印框，直接打到指定打印机 |
| 易部署 | 一体化 ZIP：扩展 + Node 运行时 + 代理 +（Win）PDFtoPrinter |
| 可探测 | 代理未安装时明确提示安装，不静默回退误打 |

### 1.3 非目标（当前阶段）

- 不实现完整 JCP 套打设计器 / 拖拽排版器
- 不保证复杂跨域外链 CSS 与原页 100% 一致（建议关键样式内联）
- 不以 Linux 为一等公民（CUPS 路径可用，安装包仅 Win/Mac）
- 不上架 Chrome Web Store 强制分发（当前固定扩展 ID + 加载已解压扩展）

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│ 业务页面 (http/https)                                         │
│  jatoolsPrinter.print(myDoc, false)                          │
│  window.postMessage ←→ content bridge                        │
└──────────────────────────────┬──────────────────────────────┘
                               │ chrome.runtime.sendMessage
┌──────────────────────────────▼──────────────────────────────┐
│ Chrome 扩展 (MV3)  ID = memmopnlapcegennpipheiadaonehljd     │
│  · page/inject.js     页面世界 API                            │
│  · content/bridge.js  中继                                    │
│  · background/*       任务路由 / 预览窗 / Native Messaging     │
│  · preview/*          预览 + 系统打印对话框                    │
│  · install/*          代理未安装时的安装说明窗                  │
└──────────────────────────────┬──────────────────────────────┘
                               │ Native Messaging
                               │ host: com.printkit.host
┌──────────────────────────────▼──────────────────────────────┐
│ Native Host (Node ≥ 18)                                      │
│  · ping / getPrinters / print                                │
│  · HTML pages → 临时 HTML → Chrome/Edge headless → PDF       │
│  · macOS: lp (CUPS)                                          │
│  · Windows: PDFtoPrinter.exe（优先）/ SumatraPDF / PrintTo   │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 组件职责

| 组件 | 目录 | 职责 |
| --- | --- | --- |
| 页面 API | `extension/page/inject.js` | 注入 `jatoolsPrinter` / `printKit` / `getJCP()`；序列化 myDoc |
| Content Bridge | `extension/content/bridge.js` | `document_start` 注入脚本；`postMessage` ↔ `runtime` |
| Service Worker | `extension/background/` | 打印任务路由、预览窗、安装引导、Native 调用 |
| Preview UI | `extension/preview/` | 纸张/边距工具栏 + `@page` 渲染 + `window.print()` |
| Native Host | `native-host/` | 打印机枚举、HTML→PDF、静默送印 |
| Installer | `installer/` | 打 Win/Mac 一体化 ZIP |

## 3. 打印链路设计

### 3.1 三种入口

| 调用 | 行为 |
| --- | --- |
| `printPreview(myDoc)` | 打开预览窗，用户可改纸张/边距后系统打印 |
| `print(myDoc, true)` | 同预览路径（`showDialog=true`） |
| `print(myDoc, false)` | **静默打印**：探测 `com.printkit.host` → Native `print`；未安装则打开安装说明，**不自动回退** |

设计原则：**静默失败要可见**。代理缺失时返回 `HOST_NOT_INSTALLED`，并弹出安装引导；用户可点「改用预览打印」显式降级。

### 3.2 页面 → 扩展消息流

```
inject.js
  normalizeDoc(myDoc)          // 收集 pageN HTML + stylesheets + settings
  postMessage({ source: 'printkit-page', type, id, payload })
       │
content/bridge.js
  chrome.runtime.sendMessage({ type, payload })
       │
service-worker.js
  createPrintJob / listPrinters / probeNativeHost / openInstallGuide
       │
  postMessage reply (printkit-page-reply)
```

超时：普通消息 15s；`PRINT_JOB` 180s（含 PDF 渲染与送印）。

### 3.3 myDoc 规范化

`normalizeDoc` 支持：

1. **DOM 文档**：`documents: document` → 按 `page_div_prefix + page1…pageN` 收集元素 outerHTML  
2. **元素数组 / HTML 字符串数组**  
3. **整段 HTML 字符串** → 单页  

同时收集：

- `link[rel=stylesheet]` / `<style>`（尽量带入预览与 PDF）
- `settings`（纸张、边距、方向、份数、打印机名）
- `copyrights`、`title`、`overlay/dragables`（预览用）
- `done(err, result)` 回调

未找到任何页时抛错，提示放置 `page1` 等元素。

### 3.4 静默打印（Native）

```
probeNativeHost(ping)
  → nativeSend('print', { title, pages, stylesheets, settings })
    → host: htmlJobToPdf (Chrome/Edge --headless --print-to-pdf)
    → host: printPdf
         macOS  → lp -d <printer> [-n copies] [-o media=…]
         Windows → PDFtoPrinter.exe file.pdf "Printer"
                   或 SumatraPDF -print-to
                   或系统 PrintTo 关联（可能闪窗）
```

临时文件落在 `os.tmpdir()/printkit-*`；Host 日志：`printkit-host.log`。

## 4. 页面公开 API

全局对象（同对象多别名）：

- `window.jatoolsPrinter`
- `window.printKit` / `window.PrintKit`
- `window.getJCP()` → `Promise` 解析为同一 API

| 方法 | 说明 |
| --- | --- |
| `printPreview(myDoc)` | 预览 |
| `print(myDoc, showDialog=true)` | `false` 走静默 |
| `getPrinters(options?)` | 枚举打印机；未安装代理可提示安装 |
| `getDefaultPrinter()` | 默认打印机 |
| `getHostStatus()` | `{ available, version, platform, … }` |
| `openInstallGuide(reason?)` | 打开安装说明 |
| `isInstalled()` | 恒 `true`（表示页面 API 已注入） |
| `version` | 扩展 API 版本，如 `0.3.0` |

就绪事件：`window` 上派发 `printkit-ready`。

### 4.1 settings 约定（对齐 jatools）

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `paperName` | A3/A4/A5/B4/B5/Letter/Legal… | `A4` |
| `orientation` | `1` 纵向 / `2` 横向 | `1` |
| `marginTop/Right/Bottom/Left` | mm | `10` |
| `copies` | 份数 | `1` |
| `printer` / `printerName` | 目标打印机名 | 系统默认 |
| `pageWidth` / `pageHeight` | 自定义尺寸 mm | 跟随纸张 |

## 5. Native Messaging 协议

### 5.1 传输

Chrome Native Messaging：`uint32 LE 长度` + UTF-8 JSON；单消息上限 64MB。

Host 名：`com.printkit.host`  
扩展 ID（manifest 固定 `key`）：`memmopnlapcegennpipheiadaonehljd`  
**ID 不一致则 Chrome 拒绝连接。**

### 5.2 请求 / 响应

请求：

```json
{
  "action": "print",
  "requestId": "nm_…",
  "payload": {
    "title": "…",
    "pages": [{ "index": 1, "id": "page1", "html": "<div…>" }],
    "stylesheets": [{ "type": "link", "href": "…" }],
    "settings": { "paperName": "A4", "printer": "HP-xxx", "copies": 1 }
  }
}
```

| action | 说明 |
| --- | --- |
| `ping` | 探活，返回 version / platform |
| `getHostInfo` | 版本、Node、tmpdir |
| `getPrinters` | `{ name, id, isDefault, source }` 列表 |
| `getDefaultPrinter` | 默认打印机 |
| `print` | HTML→PDF→送印 |

成功：`{ ok: true, … }`；失败：`{ ok: false, error: "…" }`。

扩展侧优先用 `chrome.runtime.sendNativeMessage`（一次性）；另保留 port 长连接封装。

## 6. 扩展内部设计

### 6.1 Manifest V3 要点

- `permissions`: `storage`, `scripting`, `tabs`, `nativeMessaging`
- `host_permissions`: `<all_urls>`（业务页任意域名）
- content_scripts：`document_start` + `all_frames`
- web_accessible：`inject.js`、preview、install guide
- 固定 `key` 保证扩展 ID 稳定，便于 Native Host 白名单

### 6.2 任务（Job）模型

预览 / 安装引导路径会创建 job：

```
{
  id, createdAt, tabId, frameId,
  title, pages, stylesheets, settings,
  mode, showDialog, sourceUrl, …
}
```

- 内存 `Map` + `chrome.storage.session`（回退 `local`）持久化  
- 预览页用 `?jobId=` 拉取  
- 30 分钟过期清理  

### 6.3 错误码

| code | 含义 |
| --- | --- |
| `HOST_NOT_INSTALLED` | Native Host 未注册 / 无法连接 |
| `NATIVE_PRINT_FAILED` | Host 在线但打印失败 |

Host 缺失特征文案（如 `Specified native messaging host not found`）统一归类为未安装。

## 7. 安装与分发

### 7.1 一体化安装包（推荐）

构建：`./installer/build.sh` → `dist/PrintKit-Setup-{windows,macos}.zip`

| 平台 | 安装动作 | 扩展路径 |
| --- | --- | --- |
| Windows | `Install-PrintKit.bat` → PowerShell | `%LOCALAPPDATA%\PrintKit\extension` |
| macOS | `Install-PrintKit.command` | `~/Library/Application Support/PrintKit/extension` |

包内含：扩展副本、Native Host、便携 Node、（Windows）`PDFtoPrinter.exe`、注册/卸载脚本。

Windows 安装脚本约束：**纯 ASCII**，避免中文 Windows / 微信传文件导致编码解析失败。

### 7.2 开发者分装

1. Chrome 加载 `extension/`  
2. `native-host/scripts/install-{mac,win}.*` 注册 Host  
3. CLI 自检：`node host.js --cli ping|getPrinters`

### 7.3 用户引导

扩展 Popup + `install/guide.html`：下载链接、重新检测、改用预览打印。

## 8. 与官方 JCP 的差异

| 项 | JCP | PrintKit |
| --- | --- | --- |
| 客户端 | 闭源本地程序 | Node Native Host + 系统打印 |
| 静默打印 | 自有管道 | HTML→PDF→CUPS / PDFtoPrinter |
| 扩展分发 | 常绑特定扩展 | 固定 key，本地加载 |
| 套打设计器 | 完整工具链 | 仅预览与 overlay 字段占位 |
| CSS | 私有渲染 | 依赖页面样式 + headless Chrome |

迁移建议：业务保持 `pageN` + `settings` 结构；复杂样式尽量内联；首次部署用一体化包保证扩展 ID 与 Host 匹配。

---

## 9. 安全与边界

- Native Host 仅接受已声明扩展 ID；不对外开 HTTP 端口  
- 页面通过 content script 中继，业务页不能直接调 `nativeMessaging`  
- Host 处理不可信 HTML：经临时文件 + headless 打印，不在 Host 内执行页面脚本（以 Chrome 打印管线为准）  
- 日志落临时目录，不含完整页面 HTML（仅 action 级）  
- 权限面较大（`<all_urls>`）：为兼容任意业务域名；若收窄需按客户域名改 manifest

## 11. 质量与验证

| 场景 | 预期 |
| --- | --- |
| Demo `printPreview` | 弹出预览，纸张/边距可调，系统打印框可用 |
| `print(myDoc, false)` + Host 已装 | 无预览窗，指定打印机出纸 |
| `print(myDoc, false)` + Host 未装 | 安装说明窗；返回 `HOST_NOT_INSTALLED` |
| `getPrinters()` | 返回本机打印机；未装 Host 提示 |
| 扩展 ID 被改 | Native 连接失败；需用带固定 key 的包 |
| Windows 无 PDFtoPrinter | 可能闪窗或依赖默认 PDF 软件 |

CLI：

```bash
node native-host/host.js --cli ping
node native-host/host.js --cli getPrinters
```
